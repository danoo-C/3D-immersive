## What each completed milestone delivered

### M0 — Scaffolding

`pyproject.toml` on hatchling with a src-layout, `uv` with a committed lock
file, `ruff` + `mypy` + `pytest`, and GitHub Actions across Linux, macOS and
Windows on Python 3.11 and 3.13. CI builds the wheel and installs it into a
clean environment rather than installing editable, which is the only path that
exercises what ships.

### S0 — Listening spike

A throwaway script whose only job was to put the two riskiest decisions in the
design into someone's ears before three more milestones were built on them.
**It worked: D-37 was decided by ear.** An uncrossfaded fast orbit was
described, unprompted, as *"horrible, like a dial up tone under the sound"*
against *"a clean tone"* crossfaded.

It also handed M4 its numbers: `max_itd_samples` 39, so a convolution `nfft`
of 1024; 0.20 ms mean and 0.44 ms p99 per block for one source against a
10.7 ms budget. N-1's thirty-two simultaneous sources remain M4's to benchmark.

Two findings changed the specification — D-69 (cross-correlation and onset ITD
are different quantities, not two estimates of one) and D-70 (the crossfade's
benefit falls away as a source speeds up).

### M1 — Core model, headless

The milestone's own acceptance, verbatim: *a project can be built in code,
edited, undone, saved, reloaded and compared equal — all in pytest, with no
window open.* That is now one test, and every phase of the milestone is in it.

The `.3dim` file sorts its keys, coerces its numbers, writes no timestamp,
records the build that wrote it, and is written through a temporary file so an
interrupted save cannot truncate the project that was already there. Media
paths are relative on disk and absolute in memory; a project and its audio
survive being moved to another directory; a project whose audio has gone still
opens.

### M9 phase 1 — Tokens and groups

`theme.py` carries a `Theme`: 13 tokens, 8 channel colours, 11 groups, 46
group keys. The stylesheet is built from it and returns **bytes identical** to
what it returned before the indirection existed — the cheapest possible proof
that the phase changed no pixels. No widget anywhere names a hex, and a test
asserts it.

## Findings that changed the specification

The pattern worth noting is that the most valuable results came from tests
pointed at the *documents*, not only at the code.

- **`03-data-model.md`'s own worked example of the file format did not load.**
  The backing mix's clip referenced a media id that was not in its pool. That
  block is the first thing anyone implementing against this format reads. It
  is corrected, and a test now lifts it out of the document and opens it on
  every run.
- **`04-ui-spec.md` carried two token vocabularies for the same thirteen
  colours** — `bg-1` in its palette table, `surface.panel` in its theme-file
  example. Nobody had noticed because nothing had yet had to name one in code.
  D-74 settles it on the file's names. `04`'s ownership table was also missing
  two groups it should have listed, `tab` and `focus`.
- **The mutation-testing practice had a trap in it.** A mutation the same byte
  length as the original, restored within the same second, leaves a `.pyc`
  that Python still considers valid — so the next run silently tests the
  previous mutation. Available to every sweep since M1 phase 2. All 68
  mutations were re-run with `PYTHONDONTWRITEBYTECODE=1` and hold, so nothing
  previously recorded was wrong. The practice and the trap are now documented
  in [`09-workflow.md`](docs/09-workflow.md), which described neither.

### Mutation testing

Every plan since M1 phase 2 names the ways the code could be broken *before*
the tests are written, then applies them to the finished suite.

| | Named | Survived first run | Outstanding |
|---|---|---|---|
| M1 phase 5 | 38 | 4 | 0 |
| M9 phase 1 | 30 | 3 | 1 — equivalent, pinned by a test |
| **Total** | **68** | 7 | **1** |

The single survivor is unreachable by construction rather than untested, and
carries a test asserting why it cannot fire.

Three of M1 phase 5's four survivors were the same failure in different
clothes: **a round trip proves the reader and the writer agree, not that
either is right.** Every assertion that pins a file format has to read the
file.

## What is next

**M9 phase 2 — the `.3dimtheme` file.** Its first decision is already
identified and unmade: [`02-architecture.md`](docs/02-architecture.md) names
no module for theme file I/O, and it cannot sit in `core/io/` beside
`project_io.py`, because a theme is a UI concern and N-5 keeps `core/` to the
model.

After M9: **M2 (media)**, then **M3 (timeline)** — the first milestone that
makes a sound you arrange — then **M4**, the risk milestone.

### Known items carried forward

- **`MediaFile.missing` may want to be richer than a boolean.** If M2 finds
  media resolution wants *resolved / missing / wrong length / wrong hash*, the
  field becomes a small enum or moves to a resolution table. Nothing in the
  file changes either way, which is what makes it cheap to defer.
- **`icons.icon()` is cached, and the cache outlives a theme change.** The
  tint is read at call time as D-76 requires, and the rendered `QIcon` is then
  memoised — so M9 phase 4 must call `cache_clear()` when it switches.
  Documented in the docstring and asserted by test.
- **The golden stylesheet fixture has an expiry.** It retires the first time a
  milestone legitimately changes a colour, in a commit that says which and why.
- **M4 remains the project's largest risk**, and is the reason S0 exists. The
  full register is at the foot of [`06-roadmap.md`](docs/06-roadmap.md).

### Development environment

This is WSL2. WSLg audio works but its latency and device control make it
unsuitable for judging the preview or for the M4 benchmark — run and test on
native Windows or Linux for anything audible. WSL is fine for `pytest` on
`core/`, which needs no audio device at all, and that is partly why N-5 exists.
