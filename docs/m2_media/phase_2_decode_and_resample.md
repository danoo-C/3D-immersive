# M2 · Phase 2 — Decode and resample

**Status:** ✅ complete · **Plan:**
[plans/phase_2_decode_and_resample.md](plans/phase_2_decode_and_resample.md)

## Goal

`core/io/media.py` opens any file F-5 lists and hands back its audio as
float32 at 48 kHz, one or two channels, together with the facts a `MediaFile`
records about it. A file it cannot open is a report with a reason, never an
exception — the same split M9 drew for theme files: code raises, input
reports.

After this phase a sample on disk can become samples in memory. Nothing plays
them and nothing draws them yet.

## Scope

**In:** decoding through `soundfile`; resampling to 48 kHz through `soxr`,
and only when the source rate differs; conversion of every bit depth to
float32; the `MediaFile` fields decoding determines — `name`, `source_rate`,
`channels`, `frames` at the project rate; the report for a file that is
missing, unreadable, not audio, truncated or empty; what a file with more than
two channels becomes.

**Out:** the content hash → phase 3. Peaks → phase 4. Running on a worker
thread → phase 6, which calls this; the module itself stays synchronous and
headless. Streaming from disk rather than holding audio in RAM — the roadmap
says hold it in RAM, and `03` leaves a decoded-audio cache for later if
re-decoding turns out to be too slow. Time-stretch and pitch-shift are out of
scope for v1 ([00](../00-overview.md)).

## Acceptance

- [x] WAV, AIFF, FLAC, OGG and MP3 each decode, from fixtures generated by the
      tests rather than binaries committed to the repository — or, for any
      format the tests cannot write, one committed fixture and a note saying
      why.
- [x] Whether a fallback decoder is needed for MP3 is settled, with the
      evidence in the Notes: which `libsndfile` each platform's `soundfile`
      wheel carries, and whether it reads MP3.
- [x] Audio at 22.05, 44.1 and 96 kHz comes back at 48 kHz, with a frame count
      that follows a stated rounding rule exactly, and a test tone's frequency
      unchanged within a stated tolerance, measured rather than eyeballed.
- [x] 16-bit, 24-bit and float sources all come back float32 within ±1.
- [x] Mono stays one channel and stereo two. A file with more than two is
      handled the way the plan decides, and a test asserts it.
- [x] A missing file, a directory, a text file renamed `.wav`, a truncated

- [x] `core/io/media.py` imports no Qt and no `sounddevice` — which

## Notes

Appended while building.

**One function, `decode(path)`, and every one of F-5's formats goes through
it.** It returns float32 at 48 kHz, `(frames, channels)`, C-contiguous and
read-only — every clip of a sample shares the one array — or a refusal with a
reason a person can read. Nothing it is handed makes it raise.

### D-86: no fallback decoder, and the evidence for every platform

The acceptance asked which libsndfile each platform's wheel carries. Measured
rather than assumed: the Windows x64, macOS Intel and macOS Apple Silicon
wheels of `soundfile` 0.14.0 were downloaded and their bundled libraries
inspected, and the Linux one is what this suite runs on.

| Wheel | Bundled library | Version | MP3 |
|---|---|---|---|
| `win_amd64` | `libsndfile_x64.dll` | 1.2.2 | mpg123 compiled in |
| `macosx_10_9_x86_64` | `libsndfile_x86_64.dylib` | 1.2.2 | mpg123 compiled in |
| `macosx_11_0_arm64` | `libsndfile_arm64.dylib` | 1.2.2 | mpg123 compiled in |
| Linux (installed) | `libsndfile_x86_64.so` | 1.2.2 | reads and writes MP3 |

`soundfile` loads its own copy before any system library, so this is what
runs. A test asserting MP3 is available runs on every CI leg as the standing
check. One thing not inspected: the floor in `pyproject.toml` is 0.12, and
only the locked 0.14.0 was looked at.

### What the ±1 line means for float sources

Ticked on the reading the plan gave before any code: **integer** formats come
back within ±1, which the conversion guarantees and a test asserts; **float**
formats come back unchanged, overs included, because a float file may
legitimately hold 2.0 and clipping it on import would change the audio before
anyone heard it. `03` now says so.

### The failures are libsndfile's, the reasons are ours

libsndfile raises one exception for everything, and for the two commonest
cases it says *System error.* and *Format not recognised.* So a file that is
not there and a folder are checked before libsndfile is asked, and its words
are wrapped for the rest. A file **truncated in the middle of its data**
cannot be caught this way at all: libsndfile reads what is there and reports
that as the length. That is recorded in the plan as out of reach rather than
claimed.

### ⚠️ The sweep disproved the plan's most confident claim

Resampling a 48 kHz file anyway survived every test, because it changed no
sample: `soxr` at equal rates returns its input exactly, at every quality and
length tried. The plan, `03` and a test's docstring had all said a no-op
filter still moves samples. So the rate check is a **saving, not a
safeguard** — it skips a copy of the whole file — and two tests now say so:
one that fails if a 48 kHz file reaches the resampler, and one pinning that
`soxr` is exact at equal rates, so a version that ever stops being exact makes
the check load-bearing out loud.

### Numbers for the phases that call this

Five minutes of stereo at 44.1 kHz: 0.23 s to decode as FLAC, 0.26 s as MP3,
0.26 s to resample at `HQ` (0.38 s at `VHQ`), and 115 MB of float32 once it
is in memory. Phase 6 decodes on workers, so this is not a UI-thread cost;
it is a project-load cost, and N-4's three seconds is for a warm *peak* cache
— re-decoding every sample on load is a question M3 will have to answer.

### What the mutation sweep found

Thirteen mutations — the plan's twelve and the frame rule rounding down.
Twelve were killed on the first run; the thirteenth is the disproved claim
above, killed now by the test written for it.
